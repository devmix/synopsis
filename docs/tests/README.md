# Регрессионные тесты MCP API Synopsis

## Назначение каталога

Каталог `docs/tests/` содержит сценарии регрессионного тестирования всех 12 MCP-инструментов сервиса Synopsis. Сценарии зафиксированы на реальных данных KB (дата прогона: **2026-08-14**) и предназначены для ручного запуска при изменении API или переиндексации данных.

## Структура каталога

| Файл | Описание |
|------|----------|
| `README.md` | Этот файл — индекс, структура, runbook |
| `01_basic_tool_tests.md` | Базовые вызовы всех 12 инструментов (успешные сценарии) |
| `02_error_cases.md` | Негативные сценарии: пустой query, невалидный cursor, несуществующие ID и т.д. |
| `03_e2e_scenarios.md` | 6 E2E-сценариев (search-and-answer, entity dossier, document audit, cross-domain tracking, KB overview, analytics) |
| `04_cross_domain_scenarios.md` | Кросс-доменные сценарии: Hiring Policy (199/200/201), provenance, include_cross_domain, cross_domain_links с relation_types |
| `05_api_quality_report.md` | Отчёт качества API: метрики, положительные/отрицательные находки, drift-анализ docs/api.md vs реальность, рекомендации |

## Runbook — запуск регресса (ручной)

### Предварительные условия

1. Запущенный MCP-сервер Synopsis:
   ```bash
   make run
   # или
   ./bin/synopsis --config configs/config.default.yaml serve
   ```
2. Подключённый MCP-клиент (инструменты `synopsis_*` доступны).
3. Заполненная KB (`data/ontology` ingested): 21 документ, 271 чанк, 109 сущностей, 124 факта, 4 домена.

### Порядок выполнения

| Шаг | Файл | Действие |
|-----|------|----------|
| 1 | `01_basic_tool_tests.md` | Выполнить все базовые вызовы по порядку; сравнить фактические ответы с ожидаемыми полями; отметить PASS/FAIL |
| 2 | `02_error_cases.md` | Проверить каждый error-кейс; убедиться, что сообщения об ошибках соответствуют таблице |
| 3 | `03_e2e_scenarios.md` | Прогнать все 6 E2E-сценариев; проверить критерии прохождения на каждом шаге |
| 4 | `04_cross_domain_scenarios.md` | Проверить кросс-доменные связи, provenance, include_cross_domain |
| 5 | `05_api_quality_report.md` | Сравнить текущие метрики с зафиксированными; обновить drift-таблицу при изменениях API |

### Примечание о дрейфе данных

При переиндексации (`make rebuild`, `sync --rebuild`) данные KB могут измениться:
- IDs документов, чанков, сущностей и фактов **могут смениться**.
- Количество сущностей/фактов может измениться.
- Сценарии используют конкретные ID — при переиндексации необходимо обновить параметры вызовов.

Рекомендуется фиксировать дату последнего успешного прогона в заголовке каждого файла.
