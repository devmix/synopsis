# Бенчмарк скорости эмбеддингов (ONNX)

Дата: 2026-08-16. Команда: `synopsis model benchmark [name]` (без аргумента — все установленные модели).

## Железо и окружение

| Параметр | Значение |
|----------|----------|
| CPU | Intel Core i7-11800H @ 2.30 GHz (11th Gen), 8 ядер / 16 потоков, governor `powersave` |
| RAM | ~31 GiB |
| ONNX Runtime | 1.28.0 (CPU-only) |
| Go | go1.26.5 linux/amd64 |

## Методика

- **production** — полный путь провайдера (`GenerateEmbeddings`): токенизация + пэдинг до `seq=512` (фиксированная длина, как в инжесте/поиске) + ONNX-инференс. 3 прогрева, медиана из 9 прогонов.
- **natural seq=N** — прямой вызов ONNX-сессии без пэдинга на последовательностях реальной длины (32 / 128 / 512 токенов), тот же текст (~90 токенов). Показывает стоимость инференса «по факту».
- Текст: один абзац (~90 токенов, англ.), `batch=1`.

## Результаты

| Модель | dim | production (seq=512) | natural seq=32 | natural seq=128 | natural seq=512 |
|--------|-----|----------------------|----------------|-----------------|-----------------|
| bge-small-en-v1.5 | 384 | **87.9 ms** (67–95) | 6.2 ms, 5186 tok/s | 13.5 ms, 9475 tok/s | 90.2 ms, 5676 tok/s |
| paraphrase-multilingual-MiniLM-L12-v2 | 384 | **126.0 ms** (112–134) | 7.5 ms, 4291 tok/s | 20.9 ms, 6128 tok/s | 112.9 ms, 4536 tok/s |
| bge-m3-int8 | 1024 | **630.5 ms** (611–966) | 48.5 ms, 660 tok/s | 206.7 ms, 619 tok/s | 972.9 ms, 526 tok/s |

Значения — медианы; в скобках диапазон [min–max] для production-колонки.

## Выводы

1. **Малые модели (384 dim) одного класса**: bge-small и paraphrase дают ~90–130 ms/текст на seq=512 — разница в пределах шума. Для англоязычных корпусов bge-small быстрее; multilingual MiniLM нужен только для мультиязычности.
2. **bge-m3 на CPU медленный** (~7× медленнее малых моделей при той же длине). Это большая мультиязычная модель (568M параметров, 32 слоя); INT8-квантизация здесь экономит в основном память, а не время. Для больших корпусов на CPU лучше выбрать модель 384 dim либо укоротить последовательности.
3. **Пэдинг до 512 доминирует в стоимости коротких текстов**: production-путь всегда считает полные 512 токенов, независимо от фактической длины чанка. Для текста ~90 токенов natural seq≈90 дал бы bge-small ~20 ms вместо 87.9 (×4), bge-m3 ~250 ms вместо 630 (×2.5). Динамический пэдинг / батчинг по фактической длине — очевидное место для оптимизации инжеста (query-путь не пострадает, пока query короче чанков).
4. **Разброс между прогонами**: на bge-m3 зафиксирована межпрогоновая дисперсия ~±40% (повторный одиночный прогон: production 989 ms, natural-512 685 ms) — частотное масштабирование CPU ноутбука под длительной нагрузкой. Цифры из таблицы считать оценками порядка величины, а не гарантией.

## Ограничения

- `batch=1`, один процесс, другие нагрузки на машину влияют на результат (governor `powersave` не разгоняет ядра).
- Измерено только синхронное время инференса; кэш эмбеддингов в production обходится уникальным суффиксом текста.
